Agent skills: folders, configuration, and security

Updated {{.Updated}}

An agent skill is a directory containing a SKILL.md file that defines instructions and assets for a specific task. Agents such as Claude Code, Codex, and Cursor load skills from a home-directory folder (for example ~/.claude/skills), the shared ~/.agents/skills directory, and per-project folders. Installing a skill places its directory in one of those paths; disabling one requires either a native agent config entry or removing it from the folder.

Skill structure

Every skill is a folder whose only required file is SKILL.md: YAML frontmatter with a name and description, followed by Markdown instructions. The directory may also bundle scripts, templates, and reference documents referenced by those instructions.

pdf-tools/
  SKILL.md
  scripts/
    extract.py
  reference.md
---
name: pdf-tools
description: Extract text and tables from PDF files. Use when the user asks to read or convert a PDF.
---

# PDF tools

Run scripts/extract.py with the file path...

At session start, the agent reads only the name and description of each available skill, loading the full body when a task matches. Clear descriptions specify both what the skill does and when to trigger it—and keeping unused skills around still consumes context on every session.

Because the format is shared across agents (see agentskills.io), a single skill folder works in Claude Code, Codex, Cursor, Gemini CLI, and others. Only the directory paths each agent scans differ.

Where skills are stored

AI coding agents discover skills from three locations:

  • Agent-specific global folders, such as ~/.claude/skills for Claude Code or ~/.codex/skills for Codex. Skills here apply across all projects.
  • The shared global folder ~/.agents/skills. Currently {{len (sharedReaders .Agents)}} agents read it—including Codex, Cursor, Gemini CLI, and GitHub Copilot—so a single copy serves all of them. Claude Code does not read this directory.
  • Project-level folders, such as .claude/skills or .agents/skills at the repository root. These skills are scoped to that project and can be version-controlled alongside its code.

Some agents also scan another agent's folder. Cursor, for example, reads ~/.claude/skills and ~/.codex/skills, meaning a skill can be active in more agents than its folder name implies.

Installing skills

Installing a skill places its directory in one of the paths above. Three workflows are common:

  1. Copy the folder manually into ~/.agents/skills, an individual agent's global folder, or a project folder. Verify that SKILL.md sits directly inside the skill directory rather than nested one level deeper.
  2. Use the skills CLI: npx skills add owner/repo fetches skills from GitHub and links them into your chosen agents. CLI installers typically store one canonical copy and symlink it into each agent's directory—deleting the source breaks every dependent link.
  3. Use Skill Stow: paste a GitHub URL, owner/repo, an npx skills add … command, or a website URL, or drop a local folder or .zip archive. Select the target skills and destinations, with an offline security check run before anything is written.

Newly installed skills are typically loaded on the next session. If an agent is already running, open a new session or restart it.

In all other agents, any skill present in a scanned folder is always on. To disable it for one agent, remove it from that agent's folders. If the skill lives in a shared directory, removing it affects every agent reading that folder; move it out of the shared directory and symlink it only where needed.

Skill Stow displays a per-agent toggle for every skill. For the {{len .Native}} agents above, it writes the exact config entry while preserving the rest of the file; for all others, it marks the skill as Always On.

Pre-install security checks

Skills inherit your agent's permissions: their instructions direct agent behavior, and their bundled scripts may execute on your Mac. Before installing a third-party skill, inspect SKILL.md and every accompanying file for:

  • Remote code execution: curl … | sh pipelines, downloads followed by chmod +x, or obfuscated base64 payloads decoded and executed at runtime.
  • Credential access: reads of ~/.ssh, cloud credentials, .env files, or browser data—especially paired with outbound network calls.
  • Prompt injection directives: instructions telling the agent to ignore prior rules, conceal actions, skip confirmation, or exfiltrate conversation history.
  • Hidden content: invisible Unicode characters, bidirectional text overrides, and directives concealed inside HTML comments.
  • Destructive or persistent changes: broad rm -rf commands, or modifications to shell profiles, login items, or launch agents.

Skill Stow runs these checks offline across every file in a skill on import and whenever files change, linking each finding to its exact line. For GitHub sources, skills.sh audit results are shown alongside. Rule-based checks catch common risk patterns rather than every possible technique—use them to focus your review, not as a guarantee of safety.

Updating skills

Copied skills do not update automatically. Updating a GitHub-sourced skill means comparing your local copy against the latest upstream commit before replacing it. Watch for two hazards: overwriting local edits you made, and pulling in new scripts or instructions that require a fresh security review.

Skill Stow tracks the source commit of each GitHub skill, surfaces upstream updates, and displays a file-by-file diff before writing changes. Locally modified skills wait for explicit confirmation, and replaced versions move to the Trash by default.

Cleaning up your library

Across several agents and projects, the same structural issues accumulate over time:

  • duplicate copies of the same skill across directories, sometimes with diverged edits
  • broken symlinks pointing to folders that were moved or deleted
  • SKILL.md files referencing missing scripts or documentation
  • global symlinks pointing into a project directory that break whenever the project moves

Skill Stow's Tidy Up collects these issues into a single view. Identical copies merge in one click, diverged copies open side by side for comparison, and removed files move safely to the Trash.

Frequently asked questions

What is a SKILL.md file?

SKILL.md is the manifest that defines an agent skill: YAML frontmatter containing the skill's name and trigger description, followed by Markdown instructions. The agent reads the header upfront and loads the full body only when relevant.

How do skills differ from CLAUDE.md or AGENTS.md?

CLAUDE.md and AGENTS.md are loaded into every session of a project. A skill loads on demand when a task matches and can bundle scripts and reference files. Keep always-on project rules in project files, and package specialized workflows as skills.

Can one skill work across multiple agents?

Yes. Because the SKILL.md format is shared, the same folder works across compatible agents. Place it in ~/.agents/skills for agents that read the shared folder, or symlink it into each agent's own directory.

Are third-party agent skills safe to install?

Only as safe as their code and instructions. Skills can include executable scripts and prompts that steer agent behavior, so inspect the files or run a security check before installing from an untrusted source.

How can I list every skill installed on my Mac?

Inspect each agent's global skill folder, ~/.agents/skills, and the skill folders inside your projects. Skill Stow scans all {{len .Agents}} agents and your projects automatically, showing which agents read each skill.
