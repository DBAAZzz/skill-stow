Agent Skill 指南：目录结构、配置与安全审查

更新于 {{.Updated}}

Agent Skill 是一个包含 SKILL.md 的目录，用于为 AI Agent 定义特定任务的操作说明与辅助资源。Claude Code、Codex、Cursor 等 Agent 会从用户主目录下的专属目录（例如 ~/.claude/skills）、通用目录 ~/.agents/skills 以及各项目内的目录加载 Skill。安装只需将目录置于对应路径；如需停用，可在支持该功能的 Agent 配置中关闭，或将其从目录中移出。

Skill 的结构

每个 Skill 都是一个独立文件夹，唯一必需的文件是 SKILL.md：顶部为包含名称与简介的 YAML frontmatter，正文为 Markdown 格式的操作说明。文件夹内还可附带说明中引用的脚本、模板与参考文档。

pdf-tools/
  SKILL.md
  scripts/
    extract.py
  reference.md
---
name: pdf-tools
description: Extract text and tables from PDF files. Use when the user asks to read or convert a PDF.
---

# PDF tools

Run scripts/extract.py with the file path...

会话启动时，Agent 会预先读取所有可用 Skill 的名称与简介，仅在任务匹配时才加载正文内容。因此，清晰的简介应同时说明用途与触发条件；保留过多闲置 Skill，也会在每次会话中占用额外的上下文空间。

主流 Agent 采用相同的格式规范（详见 agentskills.io），同一份 Skill 目录可在 Claude Code、Codex、Cursor、Gemini CLI 等工具间通用，差异仅在于各自的扫描路径。

Skill 的存放位置

AI 编程 Agent 通常从三类路径发现 Skill：

  • Agent 专属全局目录：例如 Claude Code 的 ~/.claude/skills 或 Codex 的 ~/.codex/skills，其中的 Skill 在所有项目中均可用。
  • 通用全局目录 ~/.agents/skills：目前有 {{len (sharedReaders .Agents)}} 个 Agent 读取该路径，包括 Codex、Cursor、Gemini CLI 与 GitHub Copilot，放置一份即可多端共用。Claude Code 不读取该目录。
  • 项目级目录：例如项目根目录下的 .claude/skills 或 .agents/skills。这类 Skill 仅对当前项目生效，并可随代码仓库一同提交。

部分 Agent 还会跨目录读取其他 Agent 的 Skill。例如 Cursor 会同时读取 ~/.claude/skills 与 ~/.codex/skills，因此一个 Skill 的实际生效范围往往超出目录名本身。

安装 Skill

安装 Skill 的本质是将其目录放入上述路径之一，常见有三种方式：

  1. 手动复制目录：将文件夹复制到 ~/.agents/skills、某个 Agent 的专属目录或项目目录中。需确保 SKILL.md 直接位于 Skill 目录下，不要多嵌套一层目录。
  2. 使用 skills 命令行工具：运行 npx skills add owner/repo 从 GitHub 仓库拉取 Skill 并配置到所选 Agent。这类工具通常只保留一份实体副本，并在各 Agent 目录中创建符号链接——若直接删除原件，所有链接都会失效。
  3. 使用 Skill Stow：粘贴 GitHub 链接、owner/repo、npx skills add … 命令或网页地址，或直接拖入文件夹与 .zip 压缩包。选定目标 Skill 与安装位置后，每个 Skill 在写入前都会执行离线安全检查。

新安装的 Skill 通常会在下一次会话中生效。如果 Agent 正在运行，请新建会话或重启应用。

其他 Agent 扫描目录中的 Skill 均处于「始终启用」状态。若需阻止某个 Agent 加载特定 Skill，需将其从对应目录移出。如果该 Skill 位于多 Agent 共享目录中，直接移除会影响所有读取方；建议将其移出共享目录，再仅链接至需要的 Agent。

Skill Stow 为每个 Skill 提供按 Agent 划分的开关视图。针对上述 {{len .Native}} 个 Agent，应用会直接写入规范的配置项并保留文件其余内容；其余 Agent 则标注为「始终启用」。

安装前的安全审查

Skill 以当前 Agent 的权限运行：其中的指令会直接影响 Agent 行为，附带的脚本也可能在本机执行。在安装第三方来源的 Skill 前，建议通读 SKILL.md 及同目录下的所有文件，重点排查：

  • 远程代码执行：curl … | sh 管道命令、下载后执行 chmod +x，或将 base64 编码内容解码后直接运行的脚本。
  • 敏感凭据访问：读取 ~/.ssh、云服务凭据、.env 文件或浏览器数据的逻辑，尤其是伴随对外网络请求的情况。
  • 针对 Agent 的提示词注入：要求 Agent「忽略之前的指令」「不要告知用户」「跳过确认」，或将对话记录发送至外部地址。
  • 隐藏文本与混淆：不可见 Unicode 字符、双向文本控制字符，以及藏在 HTML 注释中的指令。
  • 破坏性或持久化改动：大范围路径的 rm -rf 操作，或修改 shell 配置、登录项与启动代理（LaunchAgent）。

Skill Stow 会在导入时及文件发生变更后，对 Skill 内的所有文件执行离线规则扫描，并将每条风险精确链接至代码行；来自 GitHub 的来源还会同步呈现 skills.sh 的安全审计。基于规则的检查可以发现常见风险模式，但无法穷尽所有攻击手法，它用于辅助你定位审查重点，不能替代对绝对安全的保证。

更新 Skill

本地复制的 Skill 不会自动更新。更新来自 GitHub 的 Skill 时，需要先与上游最新 commit 对比后再替换，并留意两点风险：直接覆盖会丢失你的本地修改，而更新中新增的脚本或指令同样需要重新进行安全审查。

Skill Stow 会记录每个 GitHub Skill 的来源 commit，自动列出上游存在新提交的项目，并在应用更改前展示逐文件差异。本地修改过的 Skill 会等待你确认后再处理，替换下来的旧版本默认移至废纸篓。

清理与整理

同时使用多个 Agent 和项目一段时间后，目录中通常会逐渐积累以下问题：

  • 同一 Skill 被重复复制到多个目录，甚至衍生出内容不一致的副本
  • 符号链接指向的目标目录已被移动或删除
  • SKILL.md 中引用了不存在的脚本或参考文档
  • 全局符号链接指向某个项目目录，一旦项目移动便会失效

Skill Stow 的「整理」功能会将上述问题集中呈现：内容完全一致的副本可单次点击合并，产生分歧的副本支持左右对比，所有被移除的文件均默认进入废纸篓。

常见问题

SKILL.md 是什么？

SKILL.md 是定义 Agent Skill 的核心清单文件：开头以 YAML frontmatter 声明名称与适用场景，正文以 Markdown 编写操作说明。Agent 会先读取头部元数据，仅在任务匹配时加载正文。

Skill 与 CLAUDE.md、AGENTS.md 有什么区别？

CLAUDE.md 与 AGENTS.md 会在项目的每次会话中固定加载；Skill 仅在任务需要时按需加载，并可附带脚本与参考文件。适合将长期通用的项目规范写入项目文档，将特定工作流封装为 Skill。

同一个 Skill 可以在多个 Agent 中共用吗？

可以。由于 SKILL.md 格式通用，同一份目录可在兼容的 Agent 间复用。将其放入 ~/.agents/skills 可供所有读取共享目录的 Agent 使用，也可分别链接到各 Agent 的专属目录。

安装第三方 Agent Skill 安全吗？

安全性完全取决于其内容。Skill 可能包含可执行脚本及改变 Agent 行为的指令，因此在安装来源不明的 Skill 前，务必先审查文件内容或运行安全检查。

如何查看 Mac 上已安装的全部 Skill？

需要依次检查你使用的每个 Agent 的全局目录、~/.agents/skills 以及各项目内的 Skill 目录。Skill Stow 可一次性扫描 {{len .Agents}} 个 Agent 与本地项目，并标明每个 Skill 的实际读取方。
